## Иерархия источников

1. **Согласованные требования и спецификации** — основной репозиторий EventFlow, каталог docs/specifications.
2. **План и последовательность работ** — основной репозиторий EventFlow, файл docs/DEMO_RELEASE_PLAN.md.
3. **Фактическое состояние публичной Demo** — её код и docs/PROJECT_STATUS.md в репозитории eventflow-demo.
4. **Подробные архитектурные материалы, аудиты и история** — eventflow-project-docs.
5. **Публичный Project Hub** — навигационная и справочная копия для подключения новых участников; он не переопределяет приватные источники.

Если документы расходятся, не объединять сведения автоматически: определить, какой источник отвечает за конкретный вопрос, сверить дату и фактическую реализацию, затем исправить производную сводку.

## Важные ограничения

- Наличие требования в спецификации не доказывает, что функция реализована.
- Наличие кода не доказывает, что сценарий проверен.
- Статус «проверено» присваивается только после фактического пользовательского или технического теста.
- Публичная Demo использует временное состояние SharedWorker; её нельзя описывать как production-систему или как подключённую к рабочей базе Supabase.
- Исторические SQL-файлы не являются инструкцией для запуска на актуальной базе.
- Документация и архитектурные улучшения не должны задерживать демонстрационные продукты.
